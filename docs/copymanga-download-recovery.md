# v0.1.6: 官网目录与章节下载恢复

## 现场问题与证据

用户日志中《无良公会》首次运行在章节内容 API 返回 HTTP 210 后停止, 第二次运行则在官网目录为空时停止。
这两种错误处于不同阶段。开发环境匿名连续读取同一漫画目录两次, 均为空; 再读取报错章节的官网 HTML, 也没有公开图片列表。
因此本次没有证明该漫画的站点限制已解除, 也不将匿名访问失败归因于必须登录。

代码检查还发现 CopyManga 下载批次的 API 使用当前代理, 但通用图片下载器使用默认连接, 未显式使用配置的 CopyManga 代理。

## 本次调整

- 官网目录可解密但为空时, 在新会话中重新读取资料和目录一次。仍为空或失败就报告检查失败, 不使用过期目录推进记录。
- 重试网络失败时保留首次已经获取的简介和封面。仅成功目录进入短时缓存。
- 目录日志记录实际响应主机、状态和各分组章节数, 不输出账号、Token、Cookie、代理认证信息或网页动态密钥。
- 章节 API 返回 210 时, 尝试配置的官网公开章节页, 按其 `contentKey` / `cct` 解析图片列表。
- 校验最终章节路径、非空图片列表、页面 `.comicCount` 数量和 HTTP(S) 图片地址。官网也未提供完整列表时停止, 不把回退当作成功。
- 官网和 API 的部分图片使用不同临时目录。官网临时目录后缀为 `.__website`, 避免不同来源的排序或页码混用。最终 CBZ 名称仍为原章节名称。
- CopyManga 图片请求显式使用当前代理和章节 Referer, 不向图片 CDN 发送账号 Token。其他站点保持原有下载连接行为。
- 漫画中途失败不再显示其下载已完成。批次汇总区分完成与未完成的漫画。

无需新环境变量。`CMNAS_CM_PROXY` / 系统设置中的 CopyManga 代理同时用于章节、官网回退和图片请求。
Docker 镜像仓库代理是另一套配置, 不会自动配置下载器内部请求。

## 验证范围

离线测试覆盖完整官网图片列表、数量不符、空列表、非 HTTP 图片、错误章节跳转、有限重试恢复、重试失败保留资料、代理传递、账号 Token 不发给图片 CDN、不同来源部分图片隔离, 以及失败时不打包和不推进记录。
真实官网验证只读取资料、目录和章节 HTML, 未下载漫画图片。当前开发出口下该漫画仍未提供可下载数据; 需要在 NAS 实际配置的出口下验证回退是否能取得图片列表。

本次不自动切换代理节点或域名, 不伪装成功, 不承诺解除 210。

## 协议参考

[拷贝漫画增强的公开实现](https://github.com/Byaidu/copymanga-helper)使用官网章节页提供的 `contentKey` / `cct` 读取公开图片列表。
本项目独立实现解析与完整性校验, 不执行网页脚本, 不内置浏览器。
