# 轻量验收：小型自用项目

AC-20261027 r3。依据用户：“这是一个小型项目，验收不要写太重”。本页取代此前完整矩阵作为日常交付要求；技术安全要求不变，执行与记录从简。

## 每阶段交什么

| 阶段 | 交付 | 怎么看算完成 |
| --- | --- | --- |
| S0 / S1 | 简明方案、关键决定；现有详细设计保留查阅 | 范围与下一步清楚即可，不构建空镜像，不要求逐份文档签字 |
| S2 核心 | 测试镜像 + 一页说明 | 开发者用离线样例下载并生成有效 CBZ，确认失败恢复、记录与文件安全；用户不用逐项测内部接口 |
| S3 嬉皮与界面 | 候选镜像 + 一页说明 | 用户能选漫画、订阅、下载一章，CBZ 能正常打开 |
| S4 NAS / 发布 | 正式镜像标签 + 简短更新/回退说明 | 飞牛上能更新和正常下载，原订阅及文件还在；已验证候选可直接晋升，不强制重复造包 |

从 S2 开始继续提供可拉取镜像。测试/候选不更新 latest，正式验证后再同步。不能下载的候选如实标问题，不拿清单成功冒充实际下载。

## 用户验收：正常用一遍

1. 打开页面，选一部漫画加入订阅。
2. 下载一章，能看到任务结果，生成的 CBZ 能打开。
3. 升级版再确认原订阅和文件仍在；不要求每次重复升级/回退演练。

S2 尚未接真实源时由开发者给离线样例结果；不要求用户使用命令行、模拟断网或逐张核对图片。

## 开发者只做必要检查

- 跑通本次改动相关功能，再做一次正常下载回归。
- 涉及下载/完成记录时，检查失败不会假报完成、重试不会漏页或重复计数。
- 涉及存储/升级时，检查旧数据不丢、不覆盖，必要时用临时数据做一次恢复或回退。
- 重要问题没解决就写明，不把“未测”写成“通过”。未受影响检查不反复跑。

原 C01–C36 等详细场景只作开发排查参考，按本次风险选取，不是每阶段或每次提交的全量打卡表；[原 r2 归档](reports/S1-r2-snapshot.zip)保留供查阅。常规改动开发自检即可；数据迁移、完成一致性或共同接口等重要改动才按需独立检查，不新开审批层，不重跑已经结束的 S1 评审。

## 一页交付说明只写四件事

- 镜像版本/拉取地址（提交和指纹自动记录即可）。
- 本次改了什么。
- 怎么试，实际通过了什么；未解决问题直接列出。
- 如何更新；涉及数据格式变更时补一句备份/回退方法。

不新增独立报告编号、逐项签字或重复验收文档。用户直接在对话反馈能用或问题即可，不需要填写验收表。
