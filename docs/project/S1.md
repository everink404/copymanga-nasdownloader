## S1 技术决策

这些是本阶段给出的设计选择，供独立评审和后续实施使用，不表示对应代码已存在。

| ID | 决策 | 理由/代价 |
| --- | --- | --- |
| A01 | 内置、受控 Python Source API 1.0；启动时静态登记，运行时不装插件 | 不运行 Android APK，不引入插件市场或沙箱复杂度 |
| A02 | 核心统一网络执行、队列、图片校验、文件发布和完成事实；插件只提供站点语义和访问计划 | 不让新源自行标完成、清理文件或吞掉失败 |
| A03 | 全身份固定为 source_id / comic_id / group_id / chapter_id 四元组 | 不假设章节 ID 跨分组唯一，不用标题、域名或 URL 当通用身份 |
| A04 | 元数据采用标准库 SQLite，位于原 /data 下的新目录；旧 JSON 只读保留 | 单一事务可提交完成事实与任务进度；仍须设计数据库与文件之间的恢复协议。新增存储格式，需要显式导入与旧快照回退 |
| A05 | 完成事实与范围排除分离，目录按完整扫描快照制定任务 | future/from 跳过不能算已下载，插章不能被旧名称游标吞掉 |
| A06 | 只打包经过校验且列在本章清单内的页面；产物带核心清单 | 拒绝 HTML、截断图、目录杂文件或仅非空的旧页 |
| A07 | 文件先准备和校验，持久化发布意图，再无覆盖发布，再事务提交完成，最后清理 | 解决 CBZ 已存在而记录没写入及反向不一致窗口 |
| A08 | 首版只启用嬉皮；五个旧源和未知源数据保留为停用/未验证，不自动执行 | 不承诺全源重写或解除 CopyManga 210；旧源恢复是后续明确任务 |
| A09 | 一进程一 worker，手动/定时/重试共用队列；限制重试预算 | 不为提升吞吐引入当前不需要的并发或分布式状态 |
| A10 | Web API 统一为 /api/v1；旧 API 不再作为写入新核心的旁路 | 旧订阅读取及错误提示可兼容；旧写操作明确返回需使用新版入口，不能偷偷改旧 JSON |

SQLite 数据目录要求支持本机可靠锁和原子文件操作；不承诺放在 SMB/NFS 上的数据库可安全写入。NAS 本机卷映射继续使用原 /data；实现阶段须做能力检查，不能因不支持而静默换成不安全模式。

## 组件与边界

前端 → 通用 Web API → SubscriptionService / JobRunner → SourceRegistry → SourceSession。
SourceSession 使用核心 Transport，返回 Comic/Chapter/Catalog/ImageManifest；JobRunner 驱动 ImageStore → ArchivePublisher → StateStore → Cleanup。

- SourceRegistry 只加载声明兼容 API major 的内置模块；插件禁用不删除它的数据。
- SubscriptionService 持有范围和目录快照，拒绝并发修改正在排队/运行的订阅范围。
- JobRunner 拥有成功条件、事件、停止和重试；正常 return/None 不是成功证据。
- Transport 执行插件的请求计划，应用代理、凭据范围、重试预算和源级限流。
- StateStore 统一元数据写事务；源模块和页面不得直接改 SQLite、旧 JSON、完成事实或文件路径。
- ImageStore/ArchivePublisher 只处理核心分配路径；插件不能返回任意本地路径或删除指令。

## 先行风险和不降低的条件

嬉皮只有列表、详情、目录首页和图片清单的入口调研观察。搜索结果不相关；图片 HEAD 超时；未遍历全部目录、未下载图片、未形成 CBZ。
S1 可交付契约，不声称真实源已经可用。进入 S2 前要么有获准的真实源先行验证证据，要么由用户明确接受“先做离线核心、源可用性仍未知”的风险；本轮不代替用户作该风险选择。
搜索受限是否能作为 S3 退出条件由用户决定。默认 S3 要求搜索正确和真实整章成功，不能自行降低为“有列表即可”。
