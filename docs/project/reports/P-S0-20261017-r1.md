## 4. 首版最小闭环与责任边界

建议验收路径：选嬉皮 → 浏览/搜索或已明确说明的受限发现入口 → 详情/完整目录 → 选连续范围 → 保存订阅 → 手动及定时共用入队 → 逐章下载/校验/打包 → 持久化完成 → 停止、重启或失败后恢复。不得把“无新章”“源失效”“目录未完整取得”合并为空结果。

保持内置 Python 模块、静态受控注册、一个真实启用源和一个隐藏离线源、串行 worker。离线源证明核心无站点字段依赖，同时模拟分页、错误、过期图片与重复标题；它不证明真实站点可用。不引入外部插件安装、在线阅读、跨源合并、并发下载、任意不连续范围。

S0 的核心/插件划分总体合理，建议补充以下约束，具体函数和字段留给 S1：

- **核心**拥有订阅及范围快照、任务状态、完成事实、路径分配、下载校验、打包/清理与恢复；插件不能借回调自行标完成或清理。
- **插件**拥有站点语义、ID 映射、分页解析、会话与线路选择、图片清单及必要变换规则；网络实际执行通过核心提供的机制，不能绕开限流/代理。图片变换若首源不需要，不实现通用变换引擎。
- **会话**按源及账号/配置上下文管理复用、过期刷新和关闭，区分匿名元数据、账号 API、图片 CDN。账号或代理/域名变化后旧会话及缓存失效；不逐图重登。插件声明凭据适用域和 Referer，核心保证请求及重定向边界不扩大凭据范围。
- **刷新与重试**区分网络重试、登录刷新、图片清单刷新；明确总预算，防止嵌套重试无限放大。403/404 不自动一律当作 URL 过期；按源证据分类。刷新后若页身份、数量或顺序不能证明一致，隔离旧临时页，不能仅按序号复用。
- **停止**沿用完成当前章后停止；失败章不能越过，后续章不推进。网络请求、限流和刷新须有有限等待及可解释状态，不能声称现有停止会立即中断当前请求。
- **成功**须由完整清单、可接受页面、CBZ 发布及完成记录提交共同判定；打包完成但记录失败属于可恢复异常。明确重启时如何识别并核对这份 CBZ，避免重复覆盖、虚报完成或丢失恢复材料。
