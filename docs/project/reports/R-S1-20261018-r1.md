## 必改

### M1 / P1：recovery_required 的占位与公开重试入口没有闭环

位置：DR 63、69、106、110；SC 125–126；AC C24。

触发：启动对账发现已完成章节的 CBZ 缺失或损坏，按 DR 106 将事实标为 missing/corrupt，任务进入 recovery_required。DR 63 又规定 recovery_required 保留活动订阅身份占位；SC 126 只允许 failed/interrupted/stopped 重试。新 run 还须遵守活动身份去重。

结果：普通重试不接收，新任务又不能绕过占位；“用户可修复下载”没有公开操作和状态转换可到达。此问题也会影响修复前取消、停用的行为，不能靠实施者在不同服务里各自放宽条件。

最低修订：定义本地对账完成后、reason=artifact_repair_required 的明确修复动作。可复用 retry 接口，不必增加新页面：在事务内把该占位转交给唯一的新修复 job/attempt，保留旧事实和坏产物；有 prepared 未对账意图时继续拒绝网络修复。规定可取消的边界、失败后状态与再次重试方式，不允许直接把 recovery_required 全部改成普通可重试而绕过发布对账。

验收补充：从“已 complete→文件损坏→启动对账→用户修复→恢复 complete”走公开 API 全链路，并验证重复点击只产生一个活动修复任务、未对账意图不能开下、修复失败可再次处理。不能只直接调用内部下载函数证明 C24 通过。

### M2 / P1：proof_kind=none 的重启隔离规则与恢复矩阵需要明确分界

位置：SC 67–70；DR 85、99–104、110；AC D04、C15、C22–C23。

SC 67 明确 none 页面仅在同一进程、同一清单尝试内复用，重启后必须隔离旧 generation；AC D04 也要求 none 不跨新尝试复用。但 DR 恢复矩阵的“页面已校验收据没落盘，匹配才补登记”“ZIP 构建失败，保留已验证页、重试打包”“ZIP 完成但意图未写，校验后可重建意图”没有按证明类型与完整产物边界区分。

风险不是已发布完整 CBZ 必须重新联网，而是实施者可能在重启后拿旧 none 页面补收据、继续未完成打包或混入新请求，违反声明的安全保证；另一个实施者又可能把已完整校验的 CBZ 一并丢弃，无法履行无网络对账。

最低修订：给出优先级明确的矩阵。none 的部分页面在重启/刷新/新尝试后只能保留隔离，不能进入新的网络补页或按通用恢复规则续用；stable/hash 对应的复用须明确满足何种证据。对“完整 ZIP 已构建但无意图”明确证据门槛和允许/禁止动作；对“prepared 或已发布且可核对全包”的本地产物恢复明确作为例外边界，不能用它放宽部分页复用。若选择允许完整本地页集重建包，则须显式修改 SC 的重启禁止规则并解释完整、同代证据，不能两种表述并存。

验收补充：none 在仅一页/全页但尚未构包/完整 ZIP 无意图/prepared 后四个断点重启，各自给出精确预期；前两种不得因通用 PageReceipt 恢复偷偷沿用旧页，后两种按定稿边界做本地验证。hash/stable 加对应允许复用的正例。这里的 stable 指文档正式枚举 immutable_resource，不新增枚举。

### M3 / P2：同内容修复的新产物路径缺少确定分配规则

位置：DR 36–41、74–76、89、106–110；AC C03、C24。

触发：某章 content_version=V 的文件损坏，源字节仍是 V，修复下载得到同一 content_version。DR 74 的路径只含章节身份和 content-version 前缀；DR 76 保持既有分配路径，DR 89 不覆盖不同 hash 的目标，而 DR 110 要求修复使用新 artifact 路径/代。

目前“新代”没有进入路径规则。只延长身份/内容 hash 前缀不能作为通用修复方案：完整前缀仍对应同一个版本；已分配路径或存在全长冲突时，修复会永久 ARTIFACT_CONFLICT。保留坏件与成功修复可以兼容，但需要明确路径分配策略。

最低修订：在既有产物保留时为修复的物理 artifact 分配独立稳定后缀/代标识，或规定其他无覆盖的确定路径算法；保持 chapter_key 和 content_version 不变，产物 id/路径不同。完成事务只切换当前有效 artifact，不额外累计一章。正常重复执行若已有可核验同内容有效产物，应按规则复用/对账，而非每次制造新副本；未知目标仍不得认领。

验收补充：固定内容修复、相同内容但打包元数据不同、目标路径已存在未知文件、重复修复提交四类，核对坏件留存、新路径唯一、当前事实只指一个有效产物、章数不变。无需增加多版本浏览功能。

## 可选改进与样例缺口

1. **补足正例 DTO。** SC 12 要求 Descriptor 含限流默认值，但 JSON 的 source 对象没有该字段；catalog.ordered_chapters 也只给 chapter_key/chapter_id/title/ordinal，未包含 Chapter 的完整身份。可补为完整正例，或显式标“投影/摘录，不能直接作为协议对象输入”。目前解析、key 和 fingerprint 正确，不等于全部模型验证通过。
2. **固定版本指纹编码。** manifest_version/content_version 已说明参与字段，但未像目录 fingerprint 一样给出精确数组结构和 null/缺省处理。补一个 Unicode/引号、缺 revision、transform 默认值的规范化向量以及预期 digest；避免两套实现产生不同版本。无需引入新序列化依赖。
3. **给预算恢复一个例子。** 说明页 A 429→释放 worker→另一任务→恢复 A 时的 HTTP 计数、清单刷新额度、会话 generation 仍如何继承；none 续用只有原进程/原尝试满足时允许。把“共享预算”具体到可核查账本即可，不必新增队列框架。
4. **明确 revision 与范围排除的优先级。** 已真实完成章的 revision 变化可重新核验；future 的 baseline_skipped 不应只因 revision 变化成为新章。两者分别加正反例。
5. DR 137“其他五源”应改为“其他旧源/其余四源”，避免把 CopyManga 加其余源误计成六个。这只是措辞，不影响全部保留策略。

AC C01–C32 覆盖已明显超出只验 happy path 的程度；无需为用例数量继续扩张功能。必改项需补精确预期和公开动作，不将“可按矩阵恢复”当作已经解决歧义。产品测试计划全部保持未执行。
