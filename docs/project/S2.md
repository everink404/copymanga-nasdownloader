# S2：独立下载核心测试版

镜像：`montequilla/copymanga-nasdownloader:s2-preview`（linux/amd64）。固定标签：`s2-081a2e214bab8b9b26ab5f589e0865d37736cb01`；不推进 `latest`。
代码提交：`081a2e214bab8b9b26ab5f589e0865d37736cb01`，分支 `feature/download-core`。这是 S2 离线核心，不代表嬉皮或 CopyManga 下载已可用。
两个测试标签的根指纹相同：`sha256:0d1ff39c4eed04fc88ba0e90751d1cfdfcd14cc96ae3f01620a419014e59b22f`。

## 本次内容

- 独立核心和 `/api/v1` 接口；原正式入口、Dockerfile 和镜像继续保留。内置源通过注册表接入，下载/文件/完成记录统一由核心管理。
- 串行队列、全部/仅新增/从指定章开始、任务去重、进度、停止与重试；测试页面可直接添加离线样例。
- 图片解码与哈希校验，只打包本章有效清单。图片失败保留材料、不生成 CBZ、不记完成；具备匹配哈希证明时可补下载，`none` 不跨尝试复用。
- SQLite 单 writer、发布意图、输出卷无覆盖发布和本地恢复；坏件保留，修复用新文件，不重复计章节数。
- 旧 JSON 默认只读；显式导入先备份并复核指纹，旧源保留为停用/未验证记录，不提升为已下载事实，不自动转换成活动订阅。

## 怎么试

使用仓库 `compose.s2.yaml`，创建独立测试容器；打开 `http://NAS地址:18002`。不要映射正在使用的正式数据目录。
默认场景会生成两章、共六张图片。选择“第 2 页首次失败”，运行后应看到失败且无 CBZ；点击重试应完成并能下载两份 CBZ。正常重启测试容器后，完成记录和文件仍在。

本地检查：`python -m pip install -r requirements-s2.txt`，再执行 `python -m unittest discover -s tests_core -v`。
同一 smoke 脚本用于 CI 和 NAS：`python scripts/s2_smoke.py http://NAS地址:18002`；重启后增加 `--verify-existing`。

实际验证结果：本地 18 项核心测试、53 项原功能回归通过；[CI 构建与启动/重启检查](https://github.com/everink404/copymanga-nasdownloader/actions/runs/40518145348)通过，已发布 Docker Hub。
飞牛实际拉取后通过 smoke：第 2 页失败时无 CBZ、无假完成；同一重试只创建一个后继任务，复用 1 页后完成两章；两份 CBZ 的 ZIP/页数校验通过。仅重启测试容器后，再次确认 2 章、6 页和完成记录仍在。两个标签的 NAS 拉取指纹、版本及代码提交一致。页面显示也已检查。
本机直连注册表元数据查询失败，改由 NAS 实际拉取并核对镜像版本、提交和两个标签的 RepoDigest，未把失败查询写成通过。
本机 NAS 测试容器 `cmnas-s2-test`，入口 `http://192.168.31.8:18002`；测试文件全部位于 `/vol1/1000/tset/cmnas-s2-20261027/{data,downloads,cbz}`。原正式容器保持运行。

## 更新和边界

只更新独立的 S2 容器，三个测试卷保留即可；原正式容器不用重建。回退时停止 S2，继续使用原正式容器和原目录。禁止旧、新 writer 共用原数据做在线迁移。
S3 再接嬉皮、完整浏览/搜索/筛选、正式订阅卡片和定时入口。S2 的源接口用于验证核心边界；真实账号刷新、签名过期刷新、站点访问和源配置界面尚未接入，不声称这些已实现。
这是局域网测试服务，提供离线样例操作；不作为公网部署版本。
